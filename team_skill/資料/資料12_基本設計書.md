## はじめに

本書は、新規産業廃棄物最終処分場における情報管理システムの基本設計として、要件定義書及び調達仕様書に基づき、システム全体の構成、機能、方式、非機能要件の実現方法を定義するものとする。

### 目的

本システムは、産業廃棄物最終処分場における業務のうち、産業廃棄物の受入に関する各種業務を円滑かつ効率的に進めることを目的とした情報管理システムである。システムはデータセンタ内のクラウド領域上に構築され、利用者がWebブラウザを通じてアクセスし、必要情報の登録・各種申請・情報管理を行う構成となっている。

### ネットワーク構成

本システムのネットワーク構成は、利用目的や接続対象に応じて通信経路を分離した構成とする。

通常業務では、利用者端末からクラウド領域上のシステムへはインターネット経由で接続される。

処分場内で行われる搬入受付業務では、処分場内に設置された端末およびカメラ等の外部機器がローカルネットワーク（LAN）上で接続される構成とする。

外部機器は処分場内LANにのみ接続され、クラウド環境へは直接接続しない。クラウド上の本システムからの操作指示や制御情報は、処分場内のPCを中継して外部機器へ連携される。

本システムのネットワークを構成する要素を「表 ３‑１　ネットワーク構成一覧」に示す

表 ３‑１　ネットワーク構成一覧

|  |  |  |
| --- | --- | --- |
| 項番 | ネットワーク構成要素 | 概要 |
| 1 | インターネット | クライアント端末とクラウド領域を接続するネットワーク |
| 2 | 処分場内ネットワーク | 新産業廃棄物処分場内の施設のネットワーク  処分場内のPCやトラックスケール等の外部機器が接続される |
| 3 | カメラ用ネットワーク | 事業団内ネットワーク下に構築する、カメラ画像・映像の撮影と保存を行うためのネットワーク |
| 4 | クラウド内ネットワーク | AWSのクラウド上に構築するネットワーク |
| 5 | VPNネットワーク | クラウド領域上の構成要素のメンテナンスを行うためのVPNネットワーク |

| 7 | 搬入受付用PC | 処分場内の外部機器を接続し、クラウド上のシステムから外部機器の操作を行う |
| 8 | 外部機器 | 処分場内ネットワークに接続され、搬入受付用PCを介してクラウド上のシステムと連携する |

### ハードウェア構成

本システムのハードウェア構成は、AWS上のサーバーレスアーキテクチャを前提とした構成とする。

アプリケーション実行環境、データ保存領域等は、AWSのマネージドサービスを利用し、リソースの自動スケーリング、高可用性の確保、ハードウェア障害時の影響最小化が可能な構成とする。

なお、処分場内に設置される職員の操作用PC、搬入受付用PCおよび外部機器については、クラウド基盤とは独立した現地設備として構成され、処分場内ネットワーク上で運用される。

### ソフトウェア構成

本システムのソフトウェアは、フロントエンドおよびバックエンドの双方を JavaScript/TypeScriptを用いて構築し、サーバーレス環境上で実行する構成とする。

フロントエンドは、業務担当者が操作する画面UIを提供し、業務画面の表示、入力チェック、操作イベントの制御等の処理を担う。

バックエンドは、業務処理ロジック、データ管理処理、および処分場内システムとの連携制御を担当し、API形式でフロントエンドと連携する。

フロントエンドは静的コンテンツとして配信し、バックエンド処理は要求に応じて起動されることで、効率的な処理を実現する。

サーバーレス本システムのソフトウェア構成要素を以下に示す。

#### フロントエンド

* Web画面表示機能
* 入力チェック機能
* 画面操作制御
* バックエンドAPI呼出処理

#### バックエンド

* 業務処理ロジック
* 各種申請・登録処理
* データ登録・更新・参照処理
* 外部機器操作指示情報生成（搬入受付PC向け）
* 外部機器連携制御

#### 共通・運用系

* ログ出力機能
* エラーハンドリング
* 運用監視用ログ管理

## システム方式について

### クラウドサービス

本システムは、アマゾンウェブサービスジャパン合同会社が提供するクラウドサービス Amazon Web Services（AWS） を利用して構築する。

AWSは、日本国内にデータセンタを有しており、ISMAPに登録されたクラウドサービスであることから、公共システムに求められるセキュリティおよび可用性の要件を満たすものとして選定する。

本システムにおけるAWSクラウドサービスの一覧と環境構築及び設定内容を「表 ４‑１　クラウドサービス別　環境構築及び設定内容」に示す。

表 ４‑１　クラウドサービス別　環境構築及び設定内容

|  |  |  |  |
| --- | --- | --- | --- |
| 項番 | 分類 | クラウドサービス名 | 環境構築・設定内容 |
| 1 | コンテンツ配信サービス | Amazon CloudFront | Webシステムの外部公開用エントリーポイントとして利用し、HTTPS 通信を前提とする  オリジンサービス（S3、API Gateway）への直接アクセスは抑止する構成とする  事業団の職員用ページを実装する為、IPによるアクセス制限を設定する |

### 業務継続設計

本システムに障害や計画停止が発生し、クラウド上のシステムが利用できない場合には、業務継続の観点から 紙媒体による代替運用 に切り替える。

代替運用の対象は 搬入受付業務に限定 する。

システム復旧後は、障害発生中に紙等で対応した業務内容について、システム上へ手動で登録を行い、業務情報の整合性を確保する。

## 画面遷移

本システムでは、処分場内から職員が利用するページと、排出事業者、収集運搬業者が利用するページは異なるものとし、職員用のページと事業者用のページはお互いの画面へ遷移しないものとする。

　画面遷移について、以下に示す。

### ログイン画面（職員）から

ログイン認証をし、マイページへ遷移する。

ログイン画面への遷移は、処分場内のネットワークから遷移する。

初回ログイン時には強制的にパスワード変更画面へ遷移し、パスワードの変更を行った後にマイページへ遷移するものとする。

パスワードを忘れてしまった場合には、ログイン画面からパスワード再設定URLを送信する画面へ遷移し、登録されているメールアドレスを入力しメールを送信する。

送信されたメールアドレスからは直接パスワード再設定画面へ遷移し、パスワードの再設定を可能とする。

![](data:image/png;base64...)

図 ６‑１　画面遷移図　ログイン画面（職員用ページ）

### マイページ（職員）から

マイページ（職員）には「アカウント情報メニュー」、「事業者メニュー（職員）」、「契約メニュー（職員）」、「搬入メニュー（職員）」、「搬入受付」、「精算メニュー（職員）」、「統計メニュー」、「管理メニュー」、があり、それぞれボタンを押下することで次の画面へ遷移する。

## セキュリティ設計について

### システム特性

#### 利用者特性

本システムは排出事業者、収集運搬業者および事業団職員の利用を想定する。

利用者数は1日あたり100人程度を想定する。

#### 取り扱う情報

本システムでは利用者に関する個人情報（担当者名、メールアドレス、連絡先など）を取り扱う。

また、マイナンバー等の特定個人情報は取り扱わないものとする。

#### 利用環境・ネットワーク構成

本システムはAWSサーバーレス構成を採用し、AWS上に構築されたサーバーレスアーキテクチャにより提供する。

利用者はPCおよびスマートフォンを使用し、インターネットを介してWebブラウザを用いて本システムにアクセスし、ログインして各種機能を利用することを想定する。

システム管理者は、インターネットVPNを介して本システムの管理環境にアクセスし、管理コンソールなどを用いて運用管理を実施する。

本システムは業務連携のため、外部システム（kintone、freee、バランスマン）と連携する。

### 基本方針

要件定義書に記載されたセキュリティ対応方針に準拠し、本設計におけるセキュリティ設計の基本方針を示す。

（要件定義書 P41-42 「情報セキュリティに関する事項」を参照）

#### 優先的に対処すべきセキュリティリスクへの対応方針

優先的に対処すべきセキュリティリスクについて、多層防御の観点に基づくセキュリティ対策を基本方針とし、不正アクセス対策、脆弱性対策、攻撃兆候の早期検知ならびにL3～L7層におけるサービス妨害対策を実施する。

また、AWSサーバーレス構成の特性を活かし、AWSが提供する各種サービスに備わるセキュリティ機能を積極的に活用するものとする。

#### その他セキュリティリスクへの対応方針

内部不正や設定不備などの人為的ミス、外部サービスに起因するものなど、その他のセキュリティリスクについても発生時の影響を考慮し、予防的な対策に加えて早期検知を可能とする対策を講じることで、リスクの低減を図る。

#### セキュリティ要件

設計および実装の過程で新たなセキュリティ上の懸念が生じた場合には、必要に応じて追加のセキュリティ対策を講じるものとする。

また、デジタル庁が公開するガイドラインの要求事項、実施内容、重要なセキュリティ対策の考え方従い、各工程でのセキュリティ対応状況について抜け漏れを確認して是正し、システムの脆弱性が作りこまれないように留意する。

準拠するガイドラインを以下に示す

・デジタル庁「政府情報システムにおけるセキュリティ・バイ・デザインガイドライン」

・デジタル庁「政府情報システムにおける脆弱性診断導入ガイドライン」4付録A

### 想定する脅威と優先的に対処すべきセキュリティリスク

#### 想定する脅威

・インターネット経由での第三者による不正アクセス

・サービス妨害を目的とした攻撃（DDoS攻撃等）

・利用者または管理者による内部不正、誤操作、設定不備

・外部サービスに起因するリスク

#### 優先的に対処すべきセキュリティリスク

上記の驚異のうち、基本方針から移管リスクを優先的に対処すべきものとして設定する。

・外部からの不正アクセスにより、システムの個人情報が漏洩する。

・サービス妨害を目的とした攻撃等によりシステムが長時間停止する。

### 不正アクセスに関する対策

#### 認証・認可

・ユーザーIDおよびパスワードによる認証を実施する。

・認可については、認証後のユーザーに対して アクセス可能な機能・リソースを制御する仕組みを設け、不要な権限付与を防止する。

・認証・認可の実装にあたっては、AWSが提供するマネージドサービスやセキュリティ機能の活用を前提とし、セキュリティ水準を維持する。

#### アプリケーションの脆弱性対策

・入力データに対しては、AWS Lambda 内でのバリデーションおよびエスケープ処理を実施すし、インジェクション等の脆弱性への対策とする。

・AWS Lambdaへのリクエストは AWS API Gateway を経由させ、想定外のリクエストや異常なパラメータを排除する構成とする。

・AWS LambdaのランタイムおよびOSS・ミドルウェアはAWSが管理する実行環境を利用することで、セキュリティパッチが適用された最新状態を維持する方針とする。

・API へのアクセスは認証基盤で発行されたトークンを用いた認証を必須とし、

有効期限管理および不正利用防止を考慮したトークン検証により、外部からの不正な API 利用を防止する。

#### 通信とデータの保護

・利用者とシステム間の通信については、暗号化通信を前提とし、通信経路上での盗聴や改ざんを防止する。

・認証後のセッションについては、有効期限およびタイムアウトを適切に設定し、

一定時間操作が行われない場合は自動的に無効化することで、不正利用および情報漏えいを防止する。

### サービス妨害を目的とした攻撃に関する対策

・サービス妨害（DoS／DDoS）攻撃に対しては、ネットワーク層（L3）からアプリケーション層（L7）までの対策が可能なAWSのマネージドセキュリティ機構を活用し、アプリケーション層についてはAWS WAFを用いたリクエスト制御により不正通信を防止する方針とする。

・トラフィック急増や異常リクエストに対しては、AWS基盤側での自動的な防御・制限機能を前提とし、アプリケーションへの影響を最小限に抑える。

### 監視・ログ・インシデント検知

攻撃やインシデントの兆候を早期検知できるような仕組みとして、Amazon CloudWatchを利用してログ取得・監視を行うものとする。

#### ログ取得方針

・AWS Lambda、API Gateway 等の各サービスのログはAmazon CloudWatch に集約するものとする。

・ログは改ざん防止および一定期間の証跡保持を考慮し管理するものとする。

#### 監視・検知

・Amazon CloudWatchの機能によりシステム稼働状況や異常の監視を行う。

・不正なリクエスト増加やエラー多発など、攻撃や障害の兆候を早期に検知できる構成とする。

#### インシデント対応

・異常検知時には管理者が状況を把握し、影響範囲の確認および対策を実施する。

・インシデント発生時には、原因および再発防止策を整理し、必要に応じて設計の見直しを行う。

### その他のセキュリティリスク対策

#### 内部不正・誤操作・設定不備

・AWS CDK を利用したIaCによるインフラストラクチャの管理により、手作業による設定ミスの発生を抑制する。

・内部不正、誤操作および設定不備による影響に備え、システムが扱う重要データについては定期的なバックアップを取得・管理し、障害発生時や不具合発生時には速やかに復旧可能な構成とする方針とする。

・変更履歴のログ等を管理し、変更内容を追跡可能とする。

・内部不正、誤操作および設定不備によるリスク低減のため、認証・認可で設定されたアクセス権限について定期的な棚卸および監視を行い、過剰権限や設定ミスを早期に検知・是正する方針とする。

#### 外部サービスに起因するリスク

###### 想定されるリスク

・連携先APIの仕様変更・不正利用

・利用するクラウドサービスやSaaSの障害

###### 予防的対策

・利用しているOSS、外部サービス、連携先APIを一覧化し、依存関係を把握可能な状態を維持する設計とする。

・外部サービスやAPIの利用は必要最小限とし、権限・アクセス範囲を限定する構成を前提とする。

###### 早期検知の対策

・ビルド・デプロイ処理や外部サービス連携について、ログを取得し、通常と異なる挙動を検知可能な構成とする。

・外部APIやクラウドサービスの エラー増加や応答異常を監視対象とし、外部起因の異常を早期に切り分けられる設計とする。

#### メールサービス

・メール送信サービスはAWSが提供するAWS SESを利用する。

・なりすまし対策として SPF、DKIM、DMARC等の設定を行う。
